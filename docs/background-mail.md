# 后台收信与通知

当前发布平台为 macOS、Windows、Linux 和 Android。界面与后台入口共享同一个 `MailRuntime`、SQLite 连接和账户同步锁，避免重复收信或同时修改缓存。新邮件通知由原生层发出，不依赖 React 窗口。

| 平台 | 常驻与启动 | 通知与恢复 |
| --- | --- | --- |
| macOS | 关闭窗口后保留托盘进程；可在设置开启 LaunchAgent 登录启动 | 系统通知；托盘可打开邮箱、立即检查和明确退出 |
| Windows | 关闭窗口后保留托盘进程；可在设置开启用户登录启动 | 系统通知；同一用户会话内运行，避免系统服务与桌面会话隔离 |
| Linux | 关闭窗口后保留托盘进程；可在设置开启 XDG 自动启动 | 桌面通知服务；需要桌面提供托盘/AppIndicator 支持 |
| Android | `dataSync` 前台服务；服务冷启动也会初始化 Rust 引擎，无需先创建 Activity/WebView | 独立新邮件通知频道；网络恢复自动重连；系统 JobScheduler 提供持久化、联网约束的兜底检查 |

登录启动默认关闭，后台收信默认开启；全局或账户的手动/暂停策略仍然有效。托盘“退出”会结束本次运行，不使用定时拉起程序的方式对抗用户退出。没有自动收件账户时，Android 服务和定期任务会停止。

## 工作量控制

- IMAP IDLE 使用一条持久监听连接；同步使用独立的短期连接。推送突发会合并，正在同步时到来的事件会保留。
- 每个账户最多一个同步任务，全应用最多两个后台同步并行，手动操作不受后台并发额度限制。
- 桌面每轮完成后 60 秒、Android 120 秒执行兜底检查。没有新 UID、计数和 UIDVALIDITY 也没变化时，跳过完整索引、正文下载和缓存重写。
- 推送或每 15 分钟的维护轮次核对完整标记并推进历史游标；安静的兜底轮次不回填历史。
- 断线指数退避并加抖动，恢复网络后更新连接代次，避免旧 socket 继续占着监听位置。
- Android 只在数据传输期间申请最多 30 秒的短唤醒锁，等待推送时不持有。进入受限制的 Doze 状态时停止无效重试。
- Android 系统调度每次仅给只读收信检查最多 25 秒；任务停止与完成按代次区分，不会取消后来的任务，也不执行发件、移动或删除。

## 系统边界

Android 15 及以上对 `dataSync` 前台服务实行后台时长限制。服务收到超时回调后会停止，保留系统安排的定期检查；再次打开应用后恢复前台服务。JobScheduler 的最短周期为 15 分钟，实际时间由系统决定。用户强行停止应用、设备休眠断网以及厂商后台限制都可能推迟收信。设置提供后台状态和电池优化入口，不自动更改系统电池白名单。

仓库目前没有 iOS 工程。iOS 后台即时提醒和移动端被系统终止后的及时提醒，需要 APNs/FCM 等服务端推送方案、设备注册及对应部署配置；不能通过增加本机常驻服务来保证，也不使用音频、定位等无关权限保活。本次本机服务不上传邮箱凭据到额外服务器。

参考：[Android 前台服务超时](https://developer.android.com/develop/background-work/services/fgs/timeout)、[JobInfo 最短周期](https://developer.android.com/reference/android/app/job/JobInfo#getMinPeriodMillis())、[Apple 后台运行策略](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)、[Tauri 登录启动](https://v2.tauri.app/plugin/autostart/)。

## 验证路径

1. 桌面开启后台收信，关闭主窗口，从托盘重新打开；确认明确退出后进程结束。
2. Android 开启通知与自动收件账户，切后台或移除界面任务，检查前台服务及原生通知；重建服务时应重新连接实际收信引擎。
3. 切换网络、进入/退出 Doze、触发前台服务时限，检查监听代次、服务停止与系统任务兜底。
4. 运行系统调度任务，在超时或 `onStopJob` 时确认网络请求结束、同步槽释放，之后仍可正常收信。
5. 无新邮件时观察网络、CPU 和唤醒锁；不得反复执行完整 UID 索引、下载正文或持有无期限唤醒锁。
